次の不具合を直す: **$ARGUMENTS**

## 手順（順番厳守）
1. **再現**: 実際のstateに近い条件で該当関数を呼び、**エラーを目で確認する**。再現できないまま直さない。
   - 例: DOMスタブ＋実データで `renderHome()` を呼び、throwする箇所を特定する
2. **原因の特定**: 症状ではなく**原因**を1行で言い切る（例:「anchorDueが未定義関数daysBetweenを呼びホーム描画が毎回thropしていた」）。
3. **修正**: 最小限の変更で直す。周辺のリファクタは混ぜない。
4. **再発防止の検査を追加**: `qa/harness.js` に、**このバグを検出できるチェック**を足す（これが最重要。直すだけでは同じ事故が起きる）。
5. **検証**: 再現手順をもう一度流してエラーが消えたことを確認 → `node qa/harness.js` 全PASS。
6. **公開**: `git commit -m "fix: ..." && git push origin main`
7. **報告**: 原因／修正内容／**追加した回帰チェックの名前**。

## 原則
- ユーザーの報告した症状が再現できない場合は、推測で書き換えず「再現できなかった」と報告して情報を求める
- コンテンツ（daily-content.json）の問題とアプリ（index.html）の問題を混同しない
