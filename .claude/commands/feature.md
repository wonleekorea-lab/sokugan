SOKUGAN 3.0 に次の改善を入れる: **$ARGUMENTS**

**CLAUDE.md の絶対ルールと「設計の根拠」を先に読むこと。** 既存の設計を壊す変更は提案しない。

## 手順
1. **現状把握**: 該当する実装箇所を `Grep` で特定し、いま何がどう動いているかを1〜3行で述べる。推測で書き換えない。
2. **根拠を確認**（体感や思い込みで作らない）
   - 学習科学・第二言語習得の裏付けが必要なら `research-analyst` サブエージェントに調べさせる（効果量と出典つき）
   - 既に採用済みの知見（CLAUDE.md「設計の根拠」）と重複していないか確認
   - 却下済みの案（視野拡大・サブボーカリゼーション除去・LLMによるチャンク生成・10倍速読）は復活させない
3. **実装**: `index.html` を編集。単一HTML・localStorage・外部依存なしの制約を守る。既存データとの後方互換を壊さない（`defaultState` に足す形にする）。
4. **回帰チェックを足す**: 追加した機能を `qa/harness.js` が検査するようにする。**「壊れたら気づける」までが実装**。
5. **検証**: `node qa/harness.js` が全PASSするまで直す。UI描画は実際に関数を呼ぶE2Eで確認する。
6. **公開**: `git add -A && git commit -m "feat: ..." && git push origin main`
   （QAが不合格ならフックが自動でpushを止める）
7. **報告**: 何を根拠に何を変え、どの指標で効果を測れるようになったかを簡潔に。

## やらないこと
- 演出やゲーミフィケーションの追加でごまかす（数値で成長が見える方を選ぶ）
- 所要時間を大きく増やす（1日15分以内を守る）
