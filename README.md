# SOKUGAN 3.0 — Reading Fluency Lab

韓国語ネイティブのための日本語速読トレーニング。**理解度70%以上を保った読速（字/分）** だけをKPIに、毎日「昨日の自分+2.5%」を積み上げる設計。

## 🚀 起動

`start.command` をダブルクリック → http://localhost:8765/ が開く。

## 🔄 1.0からの引き継ぎ

初回起動時に旧アプリ（localStorage `jp_reading_trainer_v2`）の全セッション履歴・ストリーク・XP・自己ベストを自動移行。目標値とペーサー速度は過去実績の中央値から自動設定。1.0のデータは消さないので `index-v1-backup.html` でいつでも参照可能。

## 🧪 設計根拠（2026-06リサーチ）

- 速度と理解はトレードオフ → 理解度ゲート付き速度のみ記録（Rayner et al. 2016）
- Timed reading は13週で+25〜40%、未読文章へ転移（Chang 2010; Tran & Nation 2014）
- 反復読みの効果は新規文章に転移（repeated reading研究）
- 最適難易度は正答率80〜85% → ペーサーは3連続成功+5%/失敗-5%のステアケース（Wilson et al. 2019）
- フラッシュ識別・視野拡大系ドリルは廃止（科学的裏付けなし）
- 母語話者平均 約500字/分 を現実的な北極星として表示

## 📅 1日の流れ（約12分）

1. チャンクペーサー（文節ハイライト追従・適応速度）約1.5分
2. 瞬間キャッチ（160ms呈示→マスク→似た語から選択、3連続正解で視幅+1字・最大9字、高レベルで4→5→6択）約2分
3. 本文① ニュース初読 計測 + 設問3問
4. 本文① 反復読（初読+15%に挑戦）
5. 本文② 経営・論説 初読 計測 + 設問3問
6. 結果 — 昨日比・目標判定・今日のWins

## 📰 コンテンツのテーマ（毎夕18時更新 → 翌朝実施）

ベンチャーCEOが見逃せないトップイシューに固定（科学・論文ジャンルは廃止）:
①スタートアップ（資金調達/M&A/出口） ②AI・技術（事業価値） ③市場・経済 ④経営・組織（論説） ⑤規制・環境（WOTA関連）

速報系（①〜③）↔論説系（④⑤）の難度勾配で、硬い文体への速度転移を訓練する。

## ✅ 開始前のコンテンツ鮮度ゲート

ホーム最上部に**鮮度パネル**を常設。セッション開始前に「今日の最新コンテンツか」を必ず確認できる:

- **✅緑**: 今日（日付）の最新／翌日分を先取り生成済み（今夜分を前倒し）→ そのまま開始可
- **⚠️黄**: 表示中が過去日付 = 古い → 開始ボタンが控えめ表示になり、押すと確認ダイアログ
- **⚠️赤**: JSON未読込（内蔵教材で表示中）

機能:
- **🔄 更新を確認** ボタン: ページ再読込なしで daily-content.json を再取得。生成タスク実行後に押せば「✅最新になりました」とトースト表示
- 今日の**5本のタイトル一覧**をパネルに表示 → 開始前に中身の新しさを目視確認できる
- **🛡 QA検査済 ✅** バッジ: 前夜のQA監視AIの合格状況を併記
- 古い日付のまま開始しようとすると**確認ダイアログ**で誤って旧コンテンツを練習するのを防止

### 「今日のコンテンツが空になる」事故の防止
生成タスクは実行時刻のJSTで対象日を判定: **14時以降→翌日分を先取り**／**14時前（夜の取りこぼしを翌朝起動で実行）→当日分を即生成**。アプリを夜に閉じていても、翌朝の起動時に当日分が補完される。

## 📐 測定の精密化（ChatGPTリサーチ反映 / 2026-06）

「速く読ませる訓練を足す」のでなく「速度を測り直す」方針で3つ追加:

1. **難度補正速度**: 本文の難度（漢字率・文長・抽象語密度）で生速度を正規化。プラトー期でも、難しい文章を同速度で読めていれば実質成長として検出・表示。
2. **Deep Cloze（深層読解）**: 本文の接続表現を空所化し、論理関係の理解を1問で測定（理解度MCQとは別記録）。
3. **週次アンカー転移テスト**: 訓練と別枠で、週1回・難度固定の未訓練文を測定し「普通の読みへの転移」を検証（ラチェット・ベストに非影響）。

いずれも単一HTML＋localStorage＋日次JSONの制約内で完結。QAハーネスは101チェックに拡張。


## 📝 設問の明快さ（日本語）を検証する装置（2026-07）

「設問の日本語が分かりにくい」を**主観の申告でなく検証可能な仕組み**にした2段構え:

1. **機械リンター（ハーネス A6b・決定論）**: 選択肢の長すぎ／「の」の多重連結／抽象語過多／二重否定／選択肢の酷似を客観検出し、egregiousはFAIL。
2. **明快さ監査の記録・ゲート（ハーネス D系）**: LLMが全15問を実際に解き、①一読で分かる ②論理が一意 ③選択肢が具体的 を1〜5点で採点→`clarity-audit.json`に記録。4未満は平易に書き直し。ハーネスは「当日分の監査が存在・全問カバー・平均4以上・3未満ゼロ」をゲートするため、**監査を省略できない**（＝毎日必ず点検された証拠が残る）。

- アプリのホーム最上部に **「📝 設問明快さ 点検済 ✅ 平均X/5」** を表示。
- 各設問に **「⚠ わかりにくい」報告ボタン**。押すとlocalStorageに記録され、記録タブ→バックアップ書き出しでClaudeに渡すと該当設問を重点的に平易化。

## 🛡 QA監視の仕組み（3層防御）

1. **決定論チャンカー（単一の真実）**: チャンクは本文から毎回アプリが生成（LLM生成chunksは不使用）。文字種アトム分割で「語の内部で絶対に切らない・助詞は左へ吸着・チャンクは必ず内容語で始まる」を構造的に保証。実装は index.html の `__CHUNKER_START__`〜`__CHUNKER_END__` にあり、QAスクリプトも同じコードを共有
2. **生成タスクの自己検査**: 毎夕18時の生成後、`qa/harness.js` 全PASSになるまで完了禁止
3. **QA監視AI**（毎晩19時）: 独立にハーネス再実行 → FAILなら自動修復（repair-chunks.js）→ チャンクの自然さをLLM目視サンプリング → qa-report.json発行 → アプリに「QA検査済✅」バッジ表示
